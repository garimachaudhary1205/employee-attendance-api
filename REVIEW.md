# REVIEW.md

Defects found in the starter `app/main.py`. All of them are fixed in the submitted `app/main.py`
(the helpers were rewritten rather than reused — see rows 1–5).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |

| 1 | `compute_late_minutes`, L36–37 | Grace period compared on floored **minutes** (`minutes > 10`) instead of seconds. R2 says *strictly more than 10:00*. | Punch in at 09:40:01 (shift 09:30) returns 0; R2's own example says 10. Everything up to 09:40:59 is wrongly "on time". | Compare raw seconds (`delta > 600`), then floor to minutes. |
| 2 | `compute_late_minutes`, L35 | Shift start built with `punch_in.replace(hour, minute)` — assumes the punch's own calendar day and timezone. | Overnight shift (22:00–06:00): a 00:30 punch-in belongs to the shift that started *yesterday*; the helper compares against today's 22:00 and returns 0 instead of 150. ## Looked at and decided it was **not** a defect

* `load_dotenv()` without `override=True` — correct: a local `.env` is read, but real environment variables win, which is exactly what the contract asks for.
* `status_code=201` on `POST /employees` and `POST /attendance/punch-in` — matches the contract.
* `doc.pop("_id", None)` after `insert_one` — works, because `insert_one` mutates the dict it is given (kept the idea, moved it into serializers).
* Storing `date` as a plain `"YYYY-MM-DD"` string — correct per DATA_MODEL.md; a calendar date is deliberately not an instant.
* `MONGO_URI` / `MONGO_DB` defaults (`mongodb://localhost:27017` / `attendance_db`) — acceptable convenience defaults; nothing is hard-coded when the environment provides values.
